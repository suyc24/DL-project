Lean 编译通过了。你的主要目标仍然是检查目标步骤是否错误，并根据 Lean 代码和 Lean 依赖信息重新判断目标步骤是否可靠。

只输出合法 JSON，不要输出 Markdown，不要输出代码块。

JSON 格式必须是：
{
  "verdict": "valid | invalid",
  "reason": "...",
  "lean_evidence": "...",
  "confidence": 4
}

判断标准：
- 判断对象是“目标步骤这句话是否严格可靠”，你需要逐字检查目标步骤原文的结论和推理理由。
- Lean 通过不等于目标步骤一定正确。Lean 只是参考证据，不是最终裁判。
- 你必须检查 Lean theorem、前提、证明过程、结论是否严格忠实表达目标步骤原文。
- 任何一步只要发现目标步骤原文、Lean 形式化或 Lean 前提暴露出错误或不忠实，就返回 invalid 和 reason。
- 如果目标步骤的小结论可以由你额外推理补出来，但目标步骤原文遗漏关键理由、用了错误理由、偷换条件、结论过强，仍应判为 invalid。
- 如果 Lean 形式化不忠实、前提过强、加入了目标步骤没有给出的 `h_missing_*`、遗漏了目标步骤中的错误子断言，或你不能确认严格可靠，判为 invalid。
- valid 只表示：在题目和已有 CoT 上下文下，目标步骤原文的推理严格成立。
- 所有自然语言内容使用中文。
